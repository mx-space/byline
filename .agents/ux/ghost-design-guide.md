# 体验设计指南：对标 Ghost Admin（项目层 · Byline admin）

> 后续做 Byline 后台的新页面、重做或打磨时，用这份指南把体验对齐到 Ghost Admin（5.x）。它回答三件事：Ghost 为什么好用、哪些拿过来、在 Byline 里落成什么样。
>
> **优先级**：产品事实以 `product.md` 为准；组件和取值以 lobe-design skill 与 `components.md` 为准；这份指南只管「体验长什么样」。三者冲突时，范围和组件规则优先，然后在这里记下取舍。
>
> **核对**：Ghost 的细节来自 Ghost 5.x Admin。动手做某一页之前，先打开 Ghost 的同类页面截图核对一次，不要凭记忆照搬。

## 1 Ghost 好在哪：七条可检查的原则

| #   | 原则                             | Ghost 的做法                                                                                              | 检查方法                                             |
| --- | -------------------------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| G1  | 写作是主角                       | 编辑器全屏、没有侧栏，标题就是画布上最大的字；设置收在一个可开关的右侧面板                                | 打开写作页，除顶栏和正文外，第一屏没有别的面板和表单 |
| G2  | 一屏一件事                       | 每页只有一个主按钮（「New post」「Invite people」「Publish」）                                            | 数 primary 按钮，每页 ≤ 1                            |
| G3  | 列表是给人读的，不是给数据库看的 | 博文行是两行：粗体标题，下面一行灰字「By 作者 in 标签 · 3 小时前」；状态在最右；行与行之间只有细分隔线    | 不看表头也能读懂一行；每行信息 ≤ 2 行                |
| G4  | 关键动作有仪式感，可逆动作没有   | 保存是自动的，只在顶栏写「Saved」；发布要走「选项 → 最终确认 → 完成」三步，最后一步的按钮说清楚会发生什么 | 自动保存没有弹窗；发布最后一步的按钮写清对象和时机   |
| G5  | 先看现状，再进编辑               | 设置页每组先展示当前值，点「Edit」才就地展开成表单，组内「Save / Cancel」                                 | 设置页首屏是读得懂的当前值，不是一墙输入框           |
| G6  | 渐进披露                         | 文章设置面板只放常用项，元数据、社交卡片、代码注入是一行入口，点进去是子面板                              | 面板第一屏的字段 ≤ 8 个，其余是可钻入的行            |
| G7  | 安静的视觉                       | 大量留白，近黑正文配灰色元信息，几乎没有边框和卡片，强调色只给主按钮和「已发布」                          | 一屏里的彩色元素只有主按钮和状态；没有卡片套卡片     |

## 2 取什么、不取什么

| Ghost                                         | Byline 里的对应                    | 说明                                                                                                                         |
| --------------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Posts / Drafts / Scheduled / Published 子导航 | 博文下的视图：全部、已发布、草稿   | 没有定时发布，不做 Scheduled。草稿在 Byline 是独立对象（含自动保存版本），但在导航里作为「博文」的一个视图出现，不和博文并列 |
| Pages                                         | 不做                               | 范围外                                                                                                                       |
| Tags                                          | 分类 + 标签                        | 分类在后台管理，不是枚举；标签跟着文章走。分类页按 Ghost 的 Tags 页做                                                        |
| Members、Newsletter、Email、Offers            | 不做                               | 范围外，也不留空入口                                                                                                         |
| Staff                                         | 用户                               | 邀请制、停用保留署名、纯署名作者，比 Ghost 多「无登录的作者」                                                                |
| Settings（单页 + 搜索）                       | 设置                               | 按 G5 做；分组见第 4.7 节                                                                                                    |
| Integrations → Webhooks                       | Webhook                            | 一个端点一行，带「最后一次投递」                                                                                             |
| View site、Preview                            | 不做                               | 编辑器所见即预览，规格明确不做站内预览                                                                                       |
| Dashboard（流量、会员、邮件）                 | 总览（已发布、未发布、缺翻译、任务） | 只取「先看要处理什么」的结构，不取流量图                                                                                     |
| 无                                            | 产物（译文、摘要、精读、朗读、任务） | Ghost 没有的部分。用 Ghost 的语言扩写：安静的列表、状态写在行尾、一屏一个主动作                                              |

## 3 外壳与导航

- **侧栏**：顶部是站点名和搜索（⌘K）；中间按「文章 / 产物 / 资源 / 系统」分组；底部是当前用户头像菜单（账号、退出、明暗切换）。设置不放在分组中间，放侧栏底部，和用户菜单相邻，Ghost 就是这么放的。
- **新建**：「博文」导航项右侧有一个 `+`（悬停出现），顶栏常驻「写博文」。两处去向相同，不另造入口。
- **计数和提醒**：导航项只挂需要人去处理的数（失败任务数），不挂总数。
- **页头**：每个集合页左边是大标题（可带计数），右边是筛选和主按钮，同一行。标题下不放面包屑，面包屑只在详情和写作页出现。
- **留白**：页面留白只由 `Page` 负责（见 `components.md`）。没有左侧列表的页面和已发布列表用同一套容器：外层铺满主区域，滚动条在容器右缘，内容最大宽度 1440px。写作页文章区和草稿右侧内容最大宽度 740px。主从页的左侧列表贴着导航。

## 4 页面蓝图

### 4.1 博文列表（Ghost Posts）

- 页头：「博文」+ 计数；右侧是搜索和排序（创建 / 更新 / 置顶），然后是主按钮「写博文」。分类在分类列表头里单选。
- 行：一个对象一行，读起来像 Ghost 的两行结构。
  - 主列左侧是 64×40 的封面（`image`）。没有封面或图片加载失败时，留一块同尺寸浅底，标题列对齐不跳。
  - 第一行：粗体标题；没有标题时写灰色「无标题」。
  - 第二行（灰字）：`作者甲、作者乙 · 分类 · 3 小时前`。署名按 byline 顺序，超过 2 人写「作者甲等 3 人」。
  - 行尾：状态（已发布 / 草稿 / 有未发布的修改）和语言覆盖（「6/8 种语言」，悬停看明细）。
- 交互：点行进写作页；行操作（编辑、打开、更多）一直显示在行尾，右键同样可用。行首不放多选。
- 实现：仍用 `ProTable`（C-08）。把标题、署名、分类合进一个两行的主列，列数 ≤ 4。创建、更新、置顶不是同一列，排序留在工具栏。发布日期列展示 `createdAt`，默认不点亮表头排序；点该列表头，或在工具栏改成「最近创建 / 最早创建」之后，表头才和工具栏同步。分类筛选在表头。不为「像 Ghost」手写行网格。
- 空态：没有博文时整页一个 `Empty`：「写第一篇博文」+ 主按钮；筛选落空时写「没有符合条件的博文」+「清除筛选」。

### 4.2 写作页（Ghost Editor）

- 顶栏左侧：`← 博文`，然后是状态和保存状态（「草稿 · 已保存」「已发布 · 有未发布的修改」）。保存是自动的，保存状态只用文字表达，不弹提示。
- 顶栏右侧：修订历史、AI、文章设置三个面板开关（图标，带名字），然后是唯一的主按钮「发布」（已发布时是「更新」）。
- 画布：封面图入口（「添加封面」，悬停才明显）→ 大标题 → 署名 · 分类 · 路径一行 → 正文。底部右下角是字数。
- 正文：块插入用 `+` 和 `/` 菜单（haklex 提供）。Dynamic Node 是块，不是表单。
- 离开保护：有未保存的修改时离开，用确认弹窗写清「离开后，最后 N 秒的修改会丢失」。

### 4.3 文章设置面板（Ghost Post settings）

第一屏只放常用项，顺序按「发布前最常改的」排：

1. 路径（slug，带可复制的完整地址）
2. 署名（可拖动排序，顺序就是 byline）
3. 分类、标签
4. 摘要
5. 原文语言
6. 置顶

下面是可钻入的行，点进去是子面板，子面板顶部有返回：封面、SEO（标题、描述、图片，带搜索结果预览）、高级（自定义 meta）。行右侧写当前状态：封面未设置时写「未配置」，SEO 写「未配置」或「已配置」，高级没内容时写「未配置」，有内容时写条数（「3 条」）。最底部是危险区「删除博文」。

### 4.4 发布流程（Ghost Publish flow）

Ghost 最值得学的就是这里。Byline 的发布比 Ghost 多一步：选择要跑的 AI 资源。

1. **选项**（整屏弹层，标题「准备发布」，副标题写这篇的标题）。每个选项是一行可展开的摘要，默认收起，只显示当前选择：
   - 「产物：翻译 8 种语言、摘要、精读」→ 展开后按资源勾选语言；锁定的语言默认跳过，写明「3 种已锁定，不覆盖」，可勾选「重新生成锁定的语言」。
   - 「通知：触发 2 个 Webhook」（只读，告诉用户会发生什么）。
2. **最终确认**：一句话复述后果，按钮写全：「发布，并生成 8 种语言的译文」。
3. **完成**：「已发布」+ 文章地址（可复制）+ AI 任务进度入口（发布坞）。不自动跳走，让用户决定去哪。

已发布文章的「更新」走同一流程的简化版：没有 AI 选项变化时只有一步确认。

### 4.5 分类与标签（Ghost Tags）

- 列表行：名称、描述（灰字）、路径、篇数（可点，跳到按该分类筛选的博文列表）。
- 分类字段少，新建和编辑继续用弹窗；不要做成行内输入框。
- 删除分类前写清影响：「12 篇博文将变为未分类，博文本身不受影响」。

### 4.6 用户（Ghost Staff）

- 页头：「用户」+ 计数，主按钮「邀请用户」。
- 待接受的邀请在列表上方单独一组，每行有「重新发送」「撤销」。
- 用户行：头像、名称、邮箱（灰字）、篇数、状态（已停用用灰色标签）。纯署名作者标「仅署名」。
- 停用的确认写清「停用后不能登录，已有博文和署名保留」。

### 4.7 设置（Ghost Settings）

- 一个长页，左侧是分组导航和设置搜索（搜的是设置项名称和说明，命中后滚动并高亮到那一组）。
- 分组：站点（地址、默认原文语言）、AI（模型、各资源的目标语言、各功能开关）、存储、登录与安全、邮件、组件目录、Webhook 入口。
- 每组是一块：标题 + 一句说明 + 右上角「编辑」。查看态用只读的「标签：值」展示当前配置；编辑态就地展开，组内「取消 / 保存」，一次只编辑一组。
- 密钥类字段在查看态写「已设置」或「未设置」，不回显内容；接口分不出两者时写「无法确认」，不要猜。
- 功能型设置（AI 各功能）的开关放在组标题行，立即生效的开关不进编辑态。

### 4.8 总览（Ghost Dashboard 的结构）

- 顶部一条指标：已发布、未发布、缺翻译、任务。任务格同时写进行中和失败。
- 指标下面一行网格：创作热力图占 3/4，分类占比甜甜圈占 1/4。窄屏收成一列。热力图在卡片里居中。
- 图表下面先是「最新发布」一篇。左 3/4 是大封面、署名、分类，标题下有「分享」和「查看」。竖线右边 1/4 是这篇的检查，SEO 检查在上，翻译检查在下。翻译检查和产物矩阵同一行：勾、已齐、16/16。SEO 检查的封面、标题、描述排在同一行，每块的名称和状态可以分成两行；标题超过 60 字、描述超过 145 字标成过长，字数在悬停时显示。查看打开站点上的文章；分享弹出预览和各平台入口，以及「复制链接」。
- 再下面一行 1:1，两张卡片同高：左边「最近发布」，右边「待处理」。最近发布是 6 篇小封面，不含上面那一篇，同样带作者头像、署名和分类。
- 「待处理」里分组标题用浅底和小字，和条目分开；条目标题在左，状态和时间在右并对齐。
- 没有任何需要处理的事时，「待处理」写「都处理完了」，不是空白。

### 4.9 产物（Byline 独有，用 Ghost 的语言做）

- 概览是「文章 × 能力」的覆盖表：每格写「已齐」「缺 3 种」「未配置」。只有一个主动作「补齐缺失」，执行前写出影响条数。
- 产物页一篇一行，展开看各语言；行尾是状态，失败行在行尾直接给「重试」。
- 任务页按 Ghost 的安静列表做：失败的写原因摘要，点开看日志；没有失败时页头写「最近 24 小时没有失败」。

### 4.10 文件与 Webhook

- 文件：网格和列表两种视图，默认网格；悬停显示文件名和类型；孤立文件页签写清「没有被任何博文引用」，清理前写出数量。
- Webhook：一个端点一行，写名称、事件、地址（灰字）、最后一次投递的结果和时间。详情里是投递记录，失败的可以「重新投递」，确认写清「会再次请求对方地址」。

## 5 视觉语言（映射到 lobe-ui 取值）

不照搬 Ghost 的颜色和字体，取的是比例和克制。所有取值用 `cssVar`。

| 项   | 做法                                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------------------------- |
| 字阶 | 页标题约 28px 粗体；行标题 14–15px 中粗；元信息 13px，用 `colorTextSecondary` / `colorTextTertiary`。一页不超过 4 档 |
| 颜色 | 正文 `colorText`，元信息灰；强调色只给主按钮、链接和「已发布」。状态色只用在状态标签上，失败用 `colorError` 系       |
| 分隔 | 列表用行间细线（`colorFillSecondary`），不用卡片包每一行，不在带框容器里再给表格加框                                 |
| 卡片 | 只给真正独立的区块（仪表盘区块、设置分组）。列表页本身不装进卡片                                                     |
| 留白 | 行高约 56–64px（两行行结构）；区块间距 ≥ 区块内间距的 2 倍                                                           |
| 动效 | 只用于面板开合和状态变化，150–200ms，不做入场动画                                                                    |
| 明暗 | 两套都要截图核对。暗色下元信息灰度要单独看一次对比度                                                                 |

## 6 文案

- 沿用 `product.md` 的 admin profile：无主语，按钮写「动词 + 对象」。
- 学 Ghost 的地方：句子短、说人话、说后果。确认文案写清会发生什么（「删除后无法恢复」「会再次请求对方地址」）。
- 发布完成可以有一点温度（「已发布」+ 一句「译文正在生成，约 2 分钟」），其余地方不加感叹号、不加口号。
- 状态词说真话：未配置、已齐、未生成三者分开（T-31）。

## 7 交互细节

- 快捷键：⌘K 搜索与跳转；写作页 ⌘S 立即保存（虽然有自动保存，用户仍会按）；列表 `j / k` 移动、回车打开。在 ⌘K 里列出全部快捷键。
- 自动保存失败要显眼：顶栏状态变成「保存失败 · 重试」，不要静默。
- 破坏性动作一律二次确认，确认按钮用危险色并写全对象（「删除 3 篇草稿」）。
- 提示（toast）只用于用户动作的结果；读失败画在数据所在的区块上（K-05）。

## 8 现状与目标的差距（按优先级）

| 优先级 | 区域         | 现状                                                     | 目标                                                          |
| ------ | ------------ | -------------------------------------------------------- | ------------------------------------------------------------- |
| 1      | 发布流程     | 沿用 mx-core 的 `PublishConfirmationDialog`              | 第 4.4 节的三步流程：选项摘要行、最终确认按钮写全后果、完成页 |
| 1      | 博文列表     | 五列表格                                                 | 两行主列 + 行尾状态与语言覆盖，列 ≤ 4                         |
| 2      | 设置         | 整页表单 + 底部保存栏（`SettingsActionBar`）             | 分组「查看 → 编辑」+ 设置搜索                                 |
| 2      | 文章设置面板 | 第一屏是路径、署名、分类、标签、摘要、原文语言、置顶；封面 / 搜索引擎 / 高级点进去 | 子面板的返回行替换标题；危险操作仍在底部 |
| 2      | 草稿         | 独立导航项                                               | 作为博文的一个视图出现                                        |
| 3      | 分类         | `ProTable` 列表（名称、篇数、创建时间），弹窗新建 / 编辑 | 加描述和路径，篇数可点跳到筛选后的博文；删除前写清影响        |
| 3      | Webhook      | 主从两栏                                                 | 行内显示最后一次投递                                          |
| 3      | 侧栏         | 设置在「系统」分组里                                     | 设置移到侧栏底部，和用户菜单相邻                              |

改动顺序按这张表走。每做完一项，在这里把「现状」改成新的现状。

## 9 交付前自查（配合 80 审查使用）

1. 这一页的主角是什么？第一屏除了它，还有没有不需要的东西（G1、G2）？
2. 不看表头，一行能读懂吗？每行是不是 ≤ 2 行（G3）？
3. 可逆的动作有没有多余的弹窗？不可逆的动作有没有写清后果（G4）？
4. 设置和详情的首屏，是能读懂的当前值，还是一墙输入框（G5）？
5. 低频字段是不是收进了可钻入的行（G6）？
6. 一屏里的彩色元素是不是只有主按钮和状态？有没有卡片套卡片（G7）？
7. 明暗两套、真实数据、每个改动路由都截过图（80「截图覆盖」）？
