# 项目规则（项目层 · Byline admin）

> 2026-10 后台整体重做时沉淀下来的设计思路和纠正。只记只对 Byline 成立的取舍；通用判据已回写到 lobe-design 5.8.0（P-02 / P-03 / P-05 / K-05 / K-10 / T-31，`LOBE-HANDROLLED-TABLE`、`LOBE-REFETCH-OVERLAY`，80 的「截图覆盖」）。组件默认值引起的问题和绕法只留在代码里，不写进这里。

## 1 设计立场

对标 Ghost、Sanity、Contentful、WordPress 这类成熟内容后台：后台是编辑每天多次打开的工作台，不是展示页。密度中偏高，第一屏回答「这篇发不发、产物齐不齐、失败要不要重试」。

两种互斥的第一屏，按页面类型选，不混用：

| 立场 | 第一屏是 | 用在 |
| --- | --- | --- |
| 对象优先 | 这篇稿、这个人、这个文件本身 | 内容、资源、系统三类页 |
| 任务优先 | 现在该处理什么 | 总览、任务页 |

重做是从业务重新排，不是逐页修补。改一页之前先问：成熟的 CMS 这块长什么样，用户在这里要做什么决定。

## 2 信息架构

- 侧栏只放对象和工作区入口，同一件事的几个视图合成页签。翻译、摘要、精读、朗读是同一件事（产物）的不同能力，合进「产物 · 概览」的页签；孤立文件合进文件页的页签。被合并的路由 `hidden: true`，仍要出现在面包屑和 ⌘K 里，所以路由树保留隐藏页，只在导航里跳过。
- 「写博文」是顶栏常驻主按钮，不是导航项。页面里不再放同样的主按钮。
- 任务入口直接挂失败数，失败是唯一需要被叫过去的理由。

## 3 页面决定

下表是 2026-10 重做后的现状。下一步的目标体验见 `ghost-design-guide.md`，两者不一致时以指南为目标，做完后回来更新这张表。

| 页面 | 决定 | 不要 |
| --- | --- | --- |
| 总览 | 指标条在上，四格是已发布、未发布、缺翻译、任务；任务格同时写进行中和失败。指标下是一行网格：创作热力图（`Heatmaps`）占 3/4 并在卡片里居中，分类占比（`DonutChart` 的 `donut`）占 1/4。图表下先是「最新发布」一篇（大封面，左 3/4，竖线右侧先是同一行的封面、标题、描述 SEO 检查，下面是翻译检查）。再下面一行 1:1 且两卡同高：左「最近发布」6 篇（小封面，不含最新那篇），右「待处理」。待处理的分组标题用浅底和小字，和条目分开；条目标题左对齐，状态和时间右对齐。封面圆角小一档，每篇带作者头像、署名和分类。进行中的任务有内容时单独成块。计数带对象（「全部 72 篇」） | 把进行中和失败拆成两格；用近 N 篇抽样代替全部文章的缺翻译；手画热力格子 |
| 博文 | 整宽表格：标题 / 封面、署名、分类、状态、发布日期。点行进写作页，行操作常驻，行首不放多选 | 列表右边留一栏空详情 |
| 草稿 | 右侧详情在改动上面放检查：封面、标题、描述写出来源和字数；翻译写出缺的语言。还没发布的稿不假装已检查翻译。检查、改动、历史用 `Surface`。正文直接铺开，没有「正文」标题。已发布但相对线上有改动的稿，标签写「改动」，主动作是「撤销改动」；还没发布过的稿仍是「删除草稿」 | 把总览那一列压缩状态原样搬过来；详情里再手画一层卡片边框；给正文再套一张卡；已发布稿上写「落后」或「删除草稿」 |
| 写作页 | 画布上方大标题，下面一行署名 · 分类 · 路径；顶栏放状态、保存、发布；右侧「文章设置」可收起 | 标题塞进侧栏表单 |
| AI 概览 | 「文章 × 能力」覆盖矩阵。翻译一格写「已齐 16/16」或「缺 3 种」，明细在悬停里；没配置目标语言写「未配置」并说明去哪配；指标叫「翻译缺口」这类带名词的说法 | 一格铺 17 个语言标签；没配置却显示「已齐」 |
| AI 产物页（译文、摘要…） | 一篇文章一行父行（「N 种语言」、汇总状态、最新时间），展开看各语言；只有一种语言时不造父行 | 同一标题平铺 16 行 |
| 任务 | 状态用 `Segmented`（含「全部」，带失败数）；类型筛选在类型列表头；结果列定宽 | 筛选换行；表头被挤成竖排；类型在工具栏和表头各放一个 |
| 设置 | 左侧标签和说明，右侧控件统一 360px；恢复默认是控件旁的图标；AI 每个功能是一个分组，开关在分组标题行，开启后才出现配置 | 每个功能一张卡只放一个开关；每个字段下一行提示 |
| 用户 | `Page` 带计数和「邀请用户」；待接受的邀请是表格上方的一张卡，没有邀请时不渲染。详情抽屉里改资料、署名文章、停用分成三块，停用在分隔线下面并写明后果 | 邀请和用户混在一张表；停用按钮贴在署名文章下面 |
| Webhook | 有端点时主从两栏；一个都没有时整页 `Empty` + 创建按钮 | 空列表 + 空详情 |

## 4 状态和数据要说真话

界面不替服务端补数。下面这些缺口在服务端补齐之前，界面按「不知道」画，不要画成 0 或「已完成」：

- 分页只看 `totalPages`（或 `total / size`），服务端会丢掉 `hasNextPage`。
- 密钥类字段回来是空字符串，「已设置」和「未设置」分不出来，界面不显示「已配置」。
- 文件接口没有大小和「被谁引用」，不要造这两列。
- 没有 Webhook 测试接口，不放「发送测试」按钮。
- 表头排序和筛选只覆盖全集。分页接口没有对应参数时，不加只能重排或筛掉当前页的表头控件。

## 5 过程纠正

- **委托出去的页面必须亲自打开看。** 子代理报「完成」、类型检查和单测通过都不算。每个改过的路由用真实数据打开一次并截图，重点看工具栏是否换行、单元格是否被撑高、表头是否竖排、空态和加载态。2026-10 的 AI 概览和任务页就是漏了这一步被打回的。
- 路由以 `apps/admin/src/views` 的目录为准，不要凭印象拼。分类在 `/posts/category`，设置在 `/setting`，写错会被重定向回总览，看起来像「页面正常」。
- 浏览器截图偶尔落后一帧，结论前再截一次。
- 用户说「这个页面有问题」时，先查所有同类页面。双层留白是一处发现、所有页面都有。
